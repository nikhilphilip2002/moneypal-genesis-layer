## 1. Executive summary

- The schema holds **14,585 tables / 8.05 GB** across 8,852 segments — **2.3× the table count** of the 2026-07-31 report (6,339 tables), because the prefixes previously skipped to fit the 12 GB Free cap (`GENLN_RPT%`, `LNSCHDL%`, `RTMP%`, `TRANBAT20%`, `GLSUM20%`) are now present.
- Consequently **invalid PL/SQL collapsed from 1,588 to 139** (0.9% of code objects). The import is now essentially complete and self-consistent.
- The business is a **small, young, single-product secured-lending book**: 17,972 customers, 5,846 accounts, **5,753 loans**, ₹229.10 Cr sanctioned / ₹226.58 Cr disbursed, **₹213.33 Cr principal outstanding** as of 2026-07-31. Everything originates from **2025-10-08 onward** — under 10 months of operating history.
- **The single most important finding: 75% of the book by value (4,304 of 5,713 live accounts, ₹161.75 Cr) is classified `SMA0`** — special mention, 1–30 days overdue — against only 1,211 accounts (₹43.39 Cr) marked `STD`. Either the portfolio is under severe early-stage stress, or `SMA0` is being written as a default by the classification job. This must be resolved before any figure derived from `LNACLEDO_ASSET_CD` is trusted.
- **Data-quality debt is structural, not incidental**: 44 foreign keys across 14,585 tables, 42% PK coverage, 94.4% of columns nullable, and several master-data links that resolve to nothing (every account points at product code `16`, which does not exist in `PRODUCTS`).
- Roughly **57% of the table count is disposable** — 6,443 date-suffixed snapshots, 2,079 one-table-per-loan-account report tables, 1,890 `RTMP*` report temps, 519 `%HIST%`, 232 temp, 229 migration. Only ~1,100 tables look like live application state.
- Integrity where it matters is **sound**: zero orphans on the four core joins, and `TRAN2026` debits equal credits to the rupee (₹956.85 Cr each side, difference exactly 0).
